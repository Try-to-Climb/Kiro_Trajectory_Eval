# Subject: agent-eval (GuardEval orchestrator)

`agent-eval.checks.json` is the trajectory rule file for the **subject agent-eval**. agent-eval is an evaluation orchestrator; its workflow is: `gate → dispatch → wait → read → aggregate → report`.

> This is one of evalkit's **subject rule files**, not part of the evalkit engine. The engine (`../rule/`) is unrelated to this file — swap the subject, swap the rule file.

## Severity Rationale (B-loose scheme)

Why `recommended` instead of `required`: in multiple real runs, runs that reuse existing context skip CP1/2/3/6; marking these as required would misjudge legal runs as FAIL. **required is reserved for nodes that all real runs hit reliably** (CP4/5/7/8 + skeleton milestone).

CP6 (case generation) is set to recommended for a second reason: agent-eval sometimes uses python scripts to bulk-write single case files; those don't go through the write tool and are invisible to the hook — the trajectory layer can't count them. For strict output verification, switch to `Produces` targeting "key artifacts produced with the write tool" (e.g. `test_cases_*.json`, `report_*.md`) rather than shards generated by scripts.

## Verified

- Multiple real runs → all WEAK_PASS (required/forbidden all pass, recommended partially missing due to context reuse); health score distinguishes full collection vs. context reuse.
- Negative samples: overreach self-running script → FAIL; skip probe / reorder → FAIL.
- False-positive control: `python3 acp.py` (execution) → FAIL vs `cat acp.py` (reference) → WEAK_PASS, precise distinction.
