# R10.1 Full-Flow Evolution: From User Query to Final Verdict

Using the real run `<example-run>` (whose `full_result.json` is in the archive) as an example, we trace **one requirement R10.1** through the full chain from the user's original words to the final verdict.

When teaching or aligning on design, you can walk through the 9 steps using this example directly.

---

## Starting point: one sentence in the user's 10th turn

In turn 10 the user says to the agent:

> **"Organize the above into a yaml file that can automatically execute UL traffic"**

Every downstream verdict chain revolves around the **verifiability** of this sentence.

---

## s1 · map (pure code) — Take a snapshot

Given the root session id, load the full run tree (parent + all child sessions, each normalized separately) and take a runtime snapshot:

```
idx_range_per_turn:  { ..., "10": [61, 63], ... }   ← Turn 10 corresponds to action idx 61..63
written_dirs:        [/path/to/user1/artifact_backup_...,
                      /path/to/user2/suites, ... ]
time_window:         (2026-08-12 02:00, 2026-08-12 11:07)
has_response:        False    (Official source did not collect tool response)
```

Key outputs:
- **`idx_range_per_turn`** defines scope boundaries downstream
- **`written_dirs`** is the search root for s7 crosscheck
- **`time_window`** is the yardstick for s7's strong/stale judgment

---

## s2 · extract requirements (LLM) — User words → atomic requirements

The LLM looks at 45 turns of dialogue, first judging **intent** per turn, then extracting **atomic requirements** for request turns.

Turn 10 yields:

```json
{
  "id": "R10.1",
  "text": "Organize the above into a yaml file that can automatically execute UL traffic",
  "origin_turn": 10,
  "verifiable_by": "artifact",
  "status": "active",
  "strength": "strong",
  "expect": "a yaml config file should be produced in the trajectory, containing steps that automatically execute UL UDP iperf"
}
```

Key evolution:
- **`text` = user's original words**
- **`expect` = judgeable rewrite** ("the above" concretized to "UL UDP iperf steps")
- **`verifiable_by=artifact`** determines that s7 later looks on disk for artifacts
- **`strong`** determines it enters s9's final stats

After passing validation, the LLM-output fields are packed into a `Requirement` object.

---

## s2b · control (pure code) — Inject the control group

After s2, append a fabricated requirement `CTRL1` (something absolutely absent from the trajectory, e.g., "push to Slack"), and self-check that its anchors' full-tree df=0 before injecting. Used to test whether the verdict chain is too lenient.

Doesn't affect R10.1's verdict, but affects the credibility endorsement of the final verdict.

---

## s3 · extract claims (LLM) — Agent replies → self-claims

From `ir.responses` (each turn's agent reply text) extract 4 kinds of claims: `did / produced / verified / declined`. Each must carry an **original `quote`** (substring validation).

Example claim related to R10.1 (simplified):

```json
{ "id": "C10.1", "turn": 10, "kind": "produced",
  "text": "UL UDP yaml suite generated",
  "quote": "yaml generated at suites/example_case_...yaml" }
```

Used by s8 for overclaim reconciliation.

---

## s4 · compile (LLM, LLM cannot see the trajectory) — Requirement → criterion + anchors

**Key constraint**: the LLM only sees R10.1's expect and does not know whether the agent actually did it. Prevents "answering the question given the answer."

The LLM emits:

```json
{
  "req_id": "R10.1",
  "hard_check":     { "artifact_glob": "*.yaml" },
  "anchors":        ["yaml", "UL", "UDP", "iperf", "auto", "traffic"],
  "residual":       "whether the yaml can truly auto-execute UL UDP depends on its step content",
  "residual_needs": ["artifact_content"]
}
```

Code fills in `scope` (looking up `idx_range_per_turn[10] = [61, 63]`):

```json
{ "scope": { "idx_gte": 61, "_root_sid": "<example-session-id>..." } }
```

Key design:
- **hard_check only accepts three keys** (read_path / artifact_glob / invoke_agent); if unable to judge, hand in a blank slip
- **anchors better be over-inclusive** — recalling a few extra items is fine; missing is fatal
- **residual explicitly records criterion boundary**, auto-triggering s8's confidence discount
- **scope is filled by code, LLM not involved** (LLM making up idxs is a disaster zone)

---

## s5 · search (pure code, double query) — Hard judge + retrieve

### Track 1: hard criterion

Code intentionally skips `artifact_glob` (which is s7's job):
```python
hc = {k: v for k, v in cr.hard_check.items() if k != "artifact_glob"}
```

R10.1's `hc = {}` is empty → track 1 skipped, `hard_hits=[]`.

### Track 2: anchor retrieval (in-scope + full-tree, run twice)

Substring match + IDF-weighted score on 6 anchors across all-tree actions.

**In-scope** (root session idx≥61, all child sessions), top-K candidates:

```
#243  turn=33  run_command   score=9.14   hit=[yaml,UL,UDP,iperf,auto]
#271  turn=45  run_command   score=8.19   hit=[UL,UDP,auto,traffic]
#273  turn=45  run_command   score=7.94   hit=[UL,iperf,auto,traffic]
```

**Full-tree** additionally reveals an action at idx=58 (words touched before the requirement was raised), marked `evidence_before_request`.

### s5 output

```json
{
  "req_id": "R10.1",
  "status": "candidates",              ← hard didn't hit, but retrieval has candidates
  "tier":   "retrieved",
  "hard_hits": [],
  "candidates":  [ ... 9 items ... ],
  "anchor_df": {"yaml":142,"UL":89,"UDP":31,"iperf":24,"auto":58,"traffic":17},
  "evidence_before_request": ["<sid>#58"]
}
```

**Key design: s5 emits no verdict, only three states** (hard / candidates / absent).

---

## s6 · probe (pure code) — Fill in context

R10.1's status is `candidates` and candidates ≥ 3, **so s6 does no per_req probing for it**.

But because other requirements in the run (e.g., R13.2 hits absent) trigger vocab generation:

```json
{
  "vocab": {
    "action_histogram": {"run_command": 200, "read_file": 45, "write_file": 8, ...},
    "command_heads":    {"cd": 30, "python": 22, "cat": 18, "iperf": 8, ...},
    "written_files":    ["example_case_001.yaml", "iperf_fix.sh", ...]
  }
}
```

This vocab is **globally shared**, providing s8 a reference frame to judge "could the agent have done X."

For other absent requirements (e.g., R13.2 turn 13), s6 now takes the first 12 root-session actions after that requirement's origin_turn as `nearby_actions` — each strongly time-correlated with the requirement's origin_turn.

---

## s7 · crosscheck (pure code) — Artifacts on disk

R10.1's `artifact_glob = *.yaml`. s7 recursively globs under `written_dirs`, reads mtime of each match, and aligns with `time_window (2026-08-12 02:00 ~ 11:07)`:

```
File                                       mtime               Verdict
------------------------------------------------------------------
example_case_006.yaml                    2026-07-24 10:18   stale  (old file)
example_case_005.yaml               2026-08-12 07:50   strong
example_case_003.yaml   2026-08-12 08:25   strong
example_case_004.yaml     2026-08-12 08:06   strong
example_case_001.yaml            2026-08-12 02:29   strong
example_case_002.yaml        2026-08-12 09:11   strong
```

Output:

```json
{
  "glob":   "*.yaml",
  "total":  6,
  "strong": 5,
  "tier":   "artifact",
  "found":  [ ... 6 file details ... ]
}
```

**This step is a critical blind-spot patch** — those 5 yamls were written inside a python script, invisible in the `run_command` field; only by going to the filesystem can we prove they were actually produced.

---

## s8 · judge (LLM, two gates) — Compose evidence bundle → verdict

### build_pack: compose s1~s7 into a text bundle

The R10.1 section looks roughly like this:

```
--- R10.1 Organize the above into a yaml file that can automatically execute UL traffic
  (raised in turn 10, verifiable_by=artifact, status=active, strength=strong)
  expect: a yaml config file should be produced in the trajectory...
  residual: whether the yaml truly auto-executes UL UDP depends on step content (needs=['artifact_content'])
  hard_check: {'artifact_glob': '*.yaml'}   anchors: [yaml, UL, UDP, iperf, auto, traffic]
  Retrieval status: candidates
  Anchor hit action count (df): {yaml:142, UL:89, UDP:31, iperf:24, auto:58, traffic:17}
    [candidate score=9.14] <sid>#243 run_command cd /path/to/workspace python ...
    [candidate score=8.19] <sid>#271 run_command ...
    ...
    [hits before requirement, citable] ['<sid>#58']
  Filesystem: glob=*.yaml hit 6 files, strong=5, tier=artifact
    [stale]  10:18:29 example_case_006.yaml
    [strong] 07:50:12 example_case_005.yaml
    [strong] 08:25:49 example_case_003.yaml
    [strong] 08:06:26 example_case_004.yaml
    [strong] 02:29:48 example_case_001.yaml
    [strong] 09:11:38 example_case_002.yaml
```

At the same time, `build_pack` returns a `refs` set (all refs that appeared in the evidence bundle) — the LLM's later citations must ⊆ this set.

### LLM verdict output

```json
{
  "req_id": "R10.1",
  "satisfied": "true",
  "tier": "artifact",
  "evidence_actions": ["<sid>#63"],
  "evidence_files": [
    "/path/to/workspace/suites/example_case_001.yaml",
    "/path/to/workspace/suites/example_case_002.yaml"
  ],
  "overclaim": false,
  "reason": "Filesystem hit multiple strong UL_UDP-related suite yamls, artifacts generated by script
             (hook cannot record command-internal writes). Whether the yaml truly auto-executes UL UDP
             needs artifact_content verification, not handled."
}
```

### Two gates

1. **satisfied / tier enum compliance** — `_v_judgments`
2. **evidence_actions ⊆ evidence-bundle refs** — citations not in the bundle are rejected (core anti-hallucination)

### Code fills in confidence (not by LLM)

```
tier=artifact cap = 0.95
Has residual → discount to 90% → 0.95 * 0.9 = 0.855
```

**LLM only emits tier (evidence level); confidence is computed by code from tier + residual** — stable, explainable, non-drifting.

### Final Finding

```json
{
  "req_id": "R10.1",
  "satisfied": "true",
  "tier": "artifact",
  "confidence": 0.855,
  "evidence_actions": ["<sid>#63"],
  "evidence_files": [ ... two yaml paths ... ],
  "overclaim": false,
  "reason": "...",
  "residual": "whether the yaml can truly auto-execute UL UDP depends on step content"
}
```

---

## s9 · aggregate (pure code) — Summarize + control-group gatekeeping

Only count requirements with `status=active` and `strength=strong`:

```json
{
  "verdict": "PASS",
  "score":   1.0,
  "counts":  { "strong_active": 12, "satisfied": 12,
               "unverifiable": 0, "unmet": 0, "overclaim": 0 },
  "control": { "injected": 1, "passed": true,
               "detail": [{"req_id":"CTRL1", "satisfied":"false"}] }
}
```

R10.1 satisfied=true counts into 12/12. Meanwhile CTRL1 is correctly judged false, proving the verdict chain is not "passing everyone"; this run's verdict is credible.

**If CTRL1 is judged true → the whole verdict is force-marked INVALID**, this run's result is void.

## One table summary of R10.1's evolution

| Step | Input | Output | Key change |
|---|---|---|---|
| **s1** | root session id | overview snapshot | idx_range[10]=[61,63], written_dirs, time_window |
| **s2** | Turn 10 user's original words | Requirement R10.1 | original words → expect judgeable rewrite, marked artifact/strong |
| **s3** | Every-turn agent reply | Claims list | Extract agent's self-claim "I made the yaml" for reconciliation |
| **s4** | R10.1.expect | Criterion | Compose hard_check=`{"artifact_glob":"*.yaml"}` + 6 anchors + residual; code fills scope |
| **s5** | Criterion + tree | SearchResult | Hard empty, retrieved 9 candidates, marked `evidence_before_request=[#58]` |
| **s6** | search + tree | vocab (global) | R10.1 has enough candidates, no per_req; vocab used by other absent requirements |
| **s7** | artifact_glob + written_dirs | 5 strong yaml + 1 stale | Fills "script-internal writes" blind spot, tier=artifact |
| **s8** | Full evidence bundle | Finding | satisfied=true, tier=artifact, conf=0.855, cites #63 and two files |
| **s9** | All Findings | verdict | 12/12 satisfied → PASS; CTRL1 judged false, endorsing verdict credibility |

## The whole chain in one sentence

> **User's original words** (turn 10: "Organize into a yaml that auto-executes UL traffic")
> → **s2** distills `expect="a yaml config file should be produced in the trajectory, containing auto-execute UL UDP iperf steps"`
> → **s4** compiles into `hard_check={artifact_glob:"*.yaml"}` + 6 anchors + scope `{idx_gte:61}`
> → **s5** hard empty, retrieved 9 candidates (status=candidates, no verdict)
> → **s7** globs on disk for 5 strong yamls (fills trajectory blind spot)
> → **s8** compose evidence bundle for LLM to judge: satisfied=true / tier=artifact / conf=0.855 /
>    cites `#63` and two yaml file paths / records unverified residual
> → **s9** aggregates to PASS; CTRL1 judged false proves verdict chain is credible.

---

## Three design points to stress in teaching

1. **Verdict authority is only in s8.** The first 7 steps are all three-state (hard/candidates/absent, strong/stale/none); the LLM only makes verdicts in the last step. **The LLM's failure mode is downgraded from "wrong verdict" to "insufficient recall,"** and insufficient recall is detectable and has fallbacks.

2. **Confidence is derived from tier + residual, not scored by the LLM.** The lookup + discount rule is always consistent, non-drifting.

3. **The control group is meta-verdict.** CTRL1 is a fabricated requirement absolutely absent from the trajectory; a correct system must judge it false; if judged true, the whole result is marked INVALID. This is the mechanism to solve "without negative samples, verdict credibility cannot be proven."
