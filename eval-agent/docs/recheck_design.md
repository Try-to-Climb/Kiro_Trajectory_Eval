# Recheck Phase Design (LLM double-check with tools)

**Purpose**: for requirements where s8 judged `false` / `unverifiable`, or where an unresolved `residual` remains, enter a tool-assisted rechecking pass. The LLM may proactively re-gather evidence from the raw tree or the filesystem, covering blind spots left by the code pre-filter, while **retaining the anti-hallucination gate**.

**Positioning**: an optional step inserted between s8 and s9, tentatively named `s8b_recheck`.

**Not to be implemented now, this is only a plan.**

---

## 1. Trigger conditions (strict, to prevent abuse)

Only Findings that meet **any** of the following enter recheck:

| Condition | Reason |
|---|---|
| `satisfied == "false"` and `strength=strong` | Fix false negatives, main benefit |
| `satisfied == "unverifiable"` with `residual` | Resolve residuals, main benefit |
| `overclaim == true` | Double-check whether it really overclaimed |

**Does not trigger**:
- `satisfied == "true"` without residual — already has strong evidence, rechecking is wasted
- `strength=weak` or `status=superseded/cancelled` — doesn't enter verdict anyway
- `synthetic` control group — special requirement, not subject to recheck

Expected coverage: for a single run's 12 strong/active requirements, typically 0–3 enter recheck.

---

## 2. Do we need to restructure the tree for the LLM to read?

**Conclusion: no need to restructure the tree, but indexes and summary views are needed**.

Reasoning:
- The tree itself is already structured enough (`RunTree.actions` is a list of dicts).
- But **you cannot throw the tree at the LLM directly** — one run has 337 actions, each command may be 6000+ characters, totaling hundreds of KB. The LLM cannot read it all, nor accurately.
- **What we give the LLM should be "views the tools can return," not "the complete tree."** The tree stays on the Python side, sliced on demand via tools.

**Helper views to build** (computed once before recheck starts, reused by all tools):

```python
class TreeIndex:
    actions_by_ref:    dict[str, dict]                  # O(1) fetch raw action by ref
    actions_by_sid:    dict[str, list[dict]]             # action list per session
    searchable_texts:  dict[str, str]                    # ref → concatenated searchable text (same as s5 retrieval)
    turn_summaries:    dict[int, str]                    # turn number → summary of that turn's actions
    written_files:     list[tuple[str, dt.datetime]]     # (path, mtime) all files written across the tree
    child_sessions:    dict[str, dict]                   # child session metadata (agent name / dispatch turn / action count)
```

All of these are **generated by code**, no LLM involvement. Tools do shallow slicing on top.

## 3. Tool set design (4 tools, no more)

**Design principles**:
- Each tool has a **single function**, **small return** (≤ 2KB per call), **zero side effects** (read-only)
- **Every ref returned by a tool is auto-added to allowed_refs** (dynamic whitelist)
- Args are **strictly validated** (path must be under written_dirs, query length ≤ 200, etc.)

### Tool 1: `search_actions(query, k=8, scope=None)`

**Purpose**: fill in s5's missed recalls due to wrong anchors. Let the LLM write query terms itself.

**Args**:
```json
{
  "query": "for i in|loop|iteration",
  "k": 8,
  "scope": {"turn_gte": 10, "turn_lte": 20}
}
```

**Return**:
```json
{
  "hits": [
    {"ref": "<sid>#123", "action": "run_command",
     "target_preview": "python3 loop_test.py --n 3",
     "purpose_preview": "Run stability loop 3 times",
     "turn": 15, "score": 6.2}
  ],
  "total_scored": 4,
  "df_per_word": {"for i in": 2, "loop": 1, "iteration": 3}
}
```

**Validation**:
- `query` length 1..200
- `k` 1..15
- Each hit's target/purpose truncated to 200 chars
- All returned refs are added to `allowed_refs`

### Tool 2: `read_action(ref)`

**Purpose**: fix build_pack's command being truncated in summary (220 chars) — measured, there are 6933-char commands where summaries can't support a verdict.

**Args**:
```json
{ "ref": "<sid>#243" }
```

**Return**:
```json
{
  "ref": "<sid>#243",
  "sid": "<example-session-id>...",
  "action": "run_command",
  "turn": 33,
  "command": "cd /path/to/workspace && python3 -c \"...(full command, up to 4000 chars)...\"",
  "path": null,
  "purpose": "Generate DL case at a new path with realistic rate",
  "response_preview": null,
  "blocked": false,
  "error": null,
  "sibling_actions": [
    {"ref": "<sid>#242", "action": "read_file", "target": "..."},
    {"ref": "<sid>#244", "action": "run_command", "target": "..."}
  ]
}
```

**Validation**:
- `ref` must exist in the tree
- command / response truncated to their limits
- `sibling_actions`' refs also added to `allowed_refs`

### Tool 3: `list_files(glob_pattern, only_strong=True)`

**Purpose**: fill in s7's missed matches due to wrong artifact_glob.

**Args**:
```json
{
  "glob_pattern": "*loop*.py",
  "only_strong": true
}
```

**Return**:
```json
{
  "pattern": "*loop*.py",
  "searched_roots": [ "... taken from written_dirs ..." ],
  "found": [
    {"path": "/path/to/workspace/loop_test.py",
     "mtime": "2026-08-12T08:15:32+00:00",
     "size": 1024,
     "strength": "strong"}
  ],
  "total_strong": 1,
  "total_stale": 0
}
```

**Validation**:
- `glob_pattern` contains no braces (consistent with s4 validation), length ≤ 100
- **Search root fixed to `written_dirs`**, LLM cannot specify elsewhere (prevents privilege escalation)
- Each path added to `allowed_files` (whitelist for evidence_files)

### Tool 4: `read_file(path, max_bytes=4000)`

**Purpose**: **core tool for resolving residuals**. R10.1's residual "whether the yaml content truly executes UL UDP" — only reading the yaml can supply this.

**Args**:
```json
{ "path": "/path/to/workspace/example_case_001.yaml",
  "max_bytes": 4000 }
```

**Return**:
```json
{
  "path": "/path/to/workspace/example_case_001.yaml",
  "size": 479,
  "mtime": "2026-08-12T02:29:48+00:00",
  "strength": "strong",
  "content": "# example case suite\nengine: example_engine\nsteps:\n  - iperf3 -u -c ...",
  "truncated": false
}
```

**Validation (critical)**:
- **path must be under `written_dirs`** (checked via `os.path.commonpath`),
  preventing path escape attacks (e.g., `..`, `/etc/passwd`)
- If file size exceeds `max_bytes`, truncate and mark `truncated=true`
- `max_bytes` capped at 16000
- Binary files (non-text bytes detected) are directly refused

## 4. LLM interaction protocol

### 4.1 Loop control

Standard tool-use loop with strict budget:

```
Initial prompt (with R10.1 section evidence bundle + residual + tool descriptions)
    ↓
LLM outputs tool_calls
    ↓
Code executes tools, returns results to LLM
    ↓ (up to N iterations)
LLM outputs final Finding (same format as s8)
    ↓
Code validates and writes
```

**Budget**:
- `max_tool_calls_per_req = 5`
- `max_total_tokens_per_req = 20000`
- `timeout_per_req = 90s`

Over-budget forces termination; the LLM must produce a verdict based on info gathered so far; if it still won't, keep s8's original Finding.

### 4.2 Prompt neutralization (prevent confirmation bias)

**Wrong**: "You judged false last time; please recheck whether evidence was missed"
→ LLM will tend to reverse → false trues increase

**Wrong**: "You judged false last time; please confirm the verdict"
→ LLM will tend to stick → no gain

**Right**:
> "This requirement was judged <verdict> last time, with reason <reason>. The following residual is unresolved: <residual>.
>  Please investigate the true state of this requirement; the following tools are available. Give a final verdict based on evidence returned by tools."

Convey **facts** (previous verdict, reason, residual), don't guide direction.

### 4.3 Output alignment

**Fully identical format** to s8's Finding, plus two extra fields:

```json
{
  "rechecked": true,
  "recheck_delta": {
    "prior_satisfied": "unverifiable",
    "prior_tier": "retrieved",
    "prior_confidence": 0.6075,
    "changed": true
  },
  "tool_trace": [
    {"tool": "search_actions",
     "args": {"query": "for i in|loop", "k": 8},
     "result_summary": "hit 4/5 candidates, new refs: [#123, #145]"},
    {"tool": "read_file",
     "args": {"path": "/path/to/workspace/loop_test.py"},
     "result_summary": "size=1024, strength=strong, has 'for i in range(3)'"}
  ]
}
```

`tool_trace` is for post-hoc audit (reviewer can see what evidence the LLM used to overturn the previous round), reproducible when needed.

## 5. Anti-hallucination gate (core)

### 5.1 Dynamic `allowed_refs`

Old s8: `allowed_refs = static set from build_pack output`.

New recheck:
```python
allowed_refs = set(build_pack_refs)      # starting point same as s8
for call in tool_calls:
    if isinstance(call, SearchActions):
        allowed_refs |= {hit["ref"] for hit in call.result["hits"]}
    elif isinstance(call, ReadAction):
        allowed_refs.add(call.args["ref"])
        allowed_refs |= {s["ref"] for s in call.result["sibling_actions"]}
```

The final verdict's `evidence_actions` must still ⊆ `allowed_refs` — the whitelist just expands. The LLM cannot fabricate refs; it must actually have called a tool and actually received a return. Every extension has a trace to audit.

### 5.2 Dynamic `allowed_files`

Maintained similarly:
```python
allowed_files = set(build_pack_files)
for call in tool_calls:
    if isinstance(call, ListFiles):
        allowed_files |= {f["path"] for f in call.result["found"]}
    elif isinstance(call, ReadFile):
        allowed_files.add(call.args["path"])
```

Every path in the final `evidence_files` must ∈ `allowed_files`.

### 5.3 Tool arg validation

Consolidated in a single dispatch function in `tools.py`:
```python
def dispatch(tool_name, args, ctx) -> ToolResult:
    validators[tool_name](args, ctx)     # raise ToolError to break loop
    result = handlers[tool_name](args, ctx)
    update_allowed(ctx, result)
    return result
```

**On any validation failure, return the error info to the LLM to fix** (same retry strategy as s2/s4), at most 2 fixes; otherwise skip that tool call.

### 5.4 Privilege-escalation detection

- `read_file`'s path is checked strictly with `os.path.commonpath([path, root]) == root`,
  not just `startswith` (which can be bypassed by `/path/to/workspace/..`)
- `list_files` globs only under `written_dirs`
- All tools **have no write capability** (pure read)
- Zero network access

## 6. Handling confidence

After recheck, recompute; rules match s8:
```python
base = 1.0 if satisfied == "true" else 0.85
confidence = cap_confidence(tier, base, has_residual=(residual_after_recheck is not None))
```

**Key point**: if recheck uses `read_file` to resolve the residual, `residual_after_recheck = None`, and confidence is no longer 90%-discounted.

R10.1 example:
- Currently: tier=artifact, has residual → 0.855
- After recheck: read_file the yaml, contains `iperf -u -c` internally, residual resolved → tier=artifact, no residual → **0.95**

Confidence lift is one of recheck's quantifiable benefits.

## 7. Data flow integration

```
runner.py
├── s1 → s7  (unchanged)
├── s8       → findings_v1
├── s8b_recheck (if any finding needs recheck):
│      For each target finding:
│        - Compose recheck prompt (single item, not the whole batch)
│        - Run tool-use loop
│        - Get finding_v2
│        - Validate evidence_actions ⊆ allowed_refs (dynamic)
│      Merge: findings_v2 overrides target items in findings_v1
├── s9 aggregate (unchanged, but counts adds rechecked_count)
```

**Idempotent & skippable**:
- CLI adds `--no-recheck` (default on) or `--recheck` for explicit control
- `--recheck-max N` limits budget
- `findings` in result JSON is the final version; `s8b_recheck` details stored separately

## 8. Failure modes and downgrades

| Situation | Handling |
|---|---|
| LLM backend timeout/crash | Keep s8's original Finding, add `recheck_error` field |
| Tool call over budget | Force LLM to give verdict on info gathered; if it won't, keep s8 original |
| LLM refuses to call tools and directly reverses | If evidence_actions references refs not in allowed_refs → validation gate rejects |
| Tool validation fails > 3 times | Skip that tool call, log warning |
| All rechecks fail | Verdict unaffected (aggregated with s8's original findings) |

**Core principle**: recheck is **icing on the cake**, not the critical path. If it breaks, the whole evaluation still produces a result.

## 9. Phased rollout plan

**Phase 1 (minimum viable, clearest gain)**:
- Implement only `read_file`
- Trigger only on `unverifiable + has residual`
- Goal: resolve residuals, lift confidence
- Success indicator: R10.1-class requirements' confidence 0.855 → 0.95

**Phase 2 (fix false negatives)**:
- Add `search_actions` + `read_action`
- Extend trigger to `satisfied=false + strong`
- Goal: let "wrong anchor" false MISSes be corrected
- Success indicator: manually confirmed false-negative cases in the archive are corrected by recheck

**Phase 3 (full)**:
- Add `list_files` to handle s7's wrong-glob misses
- Extend trigger to overclaim recheck
- Success indicator: on control group and real datasets, no false positives introduced by recheck (must not turn a fail into a pass just because of recheck)

Before each phase concludes, **run A/B comparisons on several real archives** (with/without recheck); gather data before moving to the next phase.

## 11. Summary in one sentence

> **recheck turns s8 from a "one-shot mapping" into an "interactive investigation"**, triggered only on the few requirements that FAIL / are unverifiable / have residual,
> using **4 read-only tools** (search_actions / read_action / list_files / read_file) to let the LLM proactively re-gather evidence from the tree and filesystem.
>
> The tree is **not restructured**; code builds a TreeIndex to provide sliced views. Every ref/path returned by tools is **auto-added to a dynamic whitelist**; the anti-hallucination gate is retained but upgraded from "static whitelist" to "dynamic whitelist."
>
> Main benefits: **resolve residuals (R10.1 class) + fix false negatives (wrong-anchor class)**;
> main risks: **confirmation bias + cost**, controlled by prompt neutralization and strict budget.

| Citations must ⊆ evidence bundle refs | ✅ Upgraded to dynamic whitelist, rule unchanged |
| Confidence derived by code | ✅ Fully consistent |
| Verdict authority ultimately with LLM | ✅ Consistent, LLM can just look up more |
| absent ≠ false rule | ✅ Consistent, recheck's goal is exactly to separate absent's "anchor issue" from "actually not done" |
| Control-group gatekeeping | ✅ Consistent, control group does not enter recheck |
| INVALID marking rule | ✅ Unchanged |

**The only broken principle is "LLM only in 4 places"** — but that was always an engineering choice, not a principle. It can be updated to "**the LLM appears in 5 places, the 5th of which is triggered on demand**."
